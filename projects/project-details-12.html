When a printer can only follow flat toolpaths, or a camera records hours of video that someone has to measure by hand, the fastest route is often to write the tool yourself. nScryptConformal: printing that follows the surface

The problem it solves

The nScrypt 3Dn is a precision direct-write printer that dispenses conductive inks through a fine nozzle held just above the part. Its print programs are written for a flat plane. Real substrates (circuit boards, coupons, moulded parts) are slightly warped or stepped, by amounts comparable to the gap itself. A program written for a flat plane will drag the nozzle through high spots and lift away from low spots, giving broken or uneven lines. Adjusting the height by hand, point by point, is slow and does not scale beyond a few lines.

How it works

  1. Parse the program. The flat print program is split into print passes (between valve-open and valve-close commands) and travel moves. The parser can rebuild the original file exactly, so nothing outside the print passes is changed.
  2. Align scan and program. The laser scanner and the print head ride on the same machine axes, so a single XY offset maps program coordinates onto scan coordinates, with a check that every print point falls inside the scanned area.
  3. Fit the surface. The scan is turned into a smooth height model: one curve per scan line for straight passes, a full 2D surface for area scans, or a curve along the path's own length for diagonal and curved passes.
  4. Plan the nozzle height. The user picks a clearance and the machine's Z-speed limit, then one of several strategies: a least-squares polynomial (smoothest), evenly spaced sample points, curvature-adaptive points that concentrate where the surface bends, or a constrained optimisation (below).
  5. Write the new program. The result is a ready-to-run nScrypt file in which every print move tracks the real surface. Plots show the surface, clearance band and toolpath for every line before anything is printed.

The interesting bit: lift early, lower late

The Z axis can only move up and down so fast. An early version handled that by smoothing the measured surface until the nozzle could keep up. That is the wrong lever: smoothing lowers a sharp peak, and the lowered peak is exactly where the nozzle then runs into the part. To clear a tall, narrow feature, the nozzle does not need to track it; it needs to start climbing before it and come down after it.

So the latest version keeps the measured surface intact and moves the machine's limits into the constraints of an optimisation problem:

  • stay as close as possible to the target gap above the surface,
  • never go below the surface plus a safety margin,
  • never change height faster than the Z axis can (with an optional acceleration limit).
Why there is always an answer. The problem is a convex quadratic program, so it has a single best solution with no local minima and no tuning knobs. Better still, a safe path always exists: take the surface floor and "dilate" it by a cone whose slope is the Z-speed limit. That envelope is the lowest path that never touches the part and never moves too fast. The software solves the optimisation and then takes the higher of its answer and that envelope, so the output is guaranteed contact-free and within machine limits even if the solver stops early.

The application

  • Toolpath Generator: a code editor with a 3D/2D viewer for writing and checking nScrypt programs, with preset patterns (line arrays, contact pads, fan-outs) that can be overlaid.
  • Conformal: the three-step load → select → configure-and-generate workflow described above.
  • Batch Conformal: apply a saved preset to a whole folder of scans, approve or reject each result, and generate all approved files at once.
  • Curved toolpaths: planned, for genuinely three-dimensional parts.

Built in Python with NumPy and SciPy for the numerics (splines, sparse linear algebra), Matplotlib for the plots and customtkinter for the interface, and released under the Apache 2.0 licence.

TrakLab: measuring motion in lab videos

The problem it solves

My magnetic-drop experiments are recorded on video: a drop sinks through thick silicone toward a magnet, a clump of nanoparticles breaks out of it, and in the cargo-transfer work that clump is caught by a second drop. The physics is in the numbers: where the drop's centre is in every frame, how fast it moves, exactly when and where the clump leaves. Measuring that by hand, frame by frame, across many runs is slow and hard to repeat. TrakLab turns a video into calibrated position and velocity data in a few clicks.

How it works

  1. Load and trim. Open a video, crop to the region of interest, downscale for speed, set the pixels-per-millimetre calibration, choose to use every k-th frame, and mark the start and end times on a scrubbable timeline.
  2. Cache. The selected frames are read once and kept in memory, so tracking and re-runs are fast. The cache is keyed on every setting that affects it and rebuilds itself automatically when one of them changes.
  3. Find the drop. A circle detector (a Hough transform) locates the drop's centre and radius in each frame, with adjustable radius range, polarity and sensitivity.
  4. Follow points. Click a feature, such as the bottom of the drop or the tip of an escaping clump, and an optical-flow point tracker follows it from frame to frame.
  5. Watch and export. Trajectories are drawn live over the video. When the run ends, TrakLab plots position and velocity against time and exports an Excel sheet and an annotated overlay video.
How the point tracker stays honest. TrakLab uses the Kanade–Lucas–Tomasi (KLT) method: it takes a small patch of pixels around the chosen point and finds where that patch has moved in the next frame, working from a coarse, blurred image down to full detail so it can follow fast motion. Each step is also checked backwards: track the point forward one frame, then track it back. If it doesn't return to where it started, the match is unreliable and is rejected rather than silently drifting.

Extras

  • Clump volume estimate: outline a dark particle clump in a frame and estimate its volume by spinning its silhouette around its axis, the same method used to measure pendant drops. The tool also reports how asymmetric the clump is, as a warning when the estimate should be treated as approximate.
  • Crop preview, zoom, pixel ruler and scale bar, plus a session log that can be saved with the results.

Built as a MATLAB App Designer application (about 2,500 lines) using the Image Processing and Computer Vision toolboxes. It produced the trajectory data for my drop-to-drop cargo transfer work.
